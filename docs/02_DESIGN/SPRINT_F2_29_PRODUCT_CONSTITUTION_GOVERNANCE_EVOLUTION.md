# 1. Mission

Define how GMRLOG evolves after F2.

The product is never “finished.”

It continuously evolves.

But never loses its identity.

F2 locked **what GMRLOG is**.

F2.29 locks **how GMRLOG may change** without becoming something else.

---

# 2. Product Constitution

Every future feature must strengthen **Digital Home**.

Never weaken it.

| Acceptance instinct | Rejection instinct |
|---------------------|--------------------|
| Feels more like GMRLOG | Feels like another platform |
| Deepens gaming culture | Chases generic social/growth tropes |
| Respects F2 freezes | Quietly contradicts them |

If a feature makes GMRLOG look like another platform, it does not belong.

Recognition filter remains Master:

> *Does this make GMRLOG more recognizable?*

North Star filter remains:

> *Does this make GMRLOG a better digital home for gaming culture?*

---

# 3. Immutable Principles

These principles **cannot change**.

They override every future decision.

| Immutable principle |
|---------------------|
| Players remain protagonists |
| Gaming culture comes before engagement |
| Trust before growth |
| Identity before metrics |
| Community before algorithms |
| Reading before scrolling |
| Discover before addiction |
| Transparency before optimization |
| Accessibility before aesthetics |
| Privacy before monetization |

Derived freezes (F2.1–F2.28) instantiate these principles.

Future work may refine surfaces.

It may not repeal these laws.

---

# 4. Evolution Rules

New features must:

| Must |
|------|
| Strengthen existing pillars |
| Never replace them |
| Never create competing philosophies |

Evolution is **additive**.

Never destructive.

Six pillars remain equal (Master).

Optional layers (Premium · commerce · AI assistance · extensibility · org tooling) remain layers — never new protagonists.

---

# 5. Feature Acceptance Framework

Every new feature must answer **YES** to:

| # | Question |
|---|----------|
| 1 | Does it strengthen Digital Home? |
| 2 | Does it improve gaming culture? |
| 3 | Does it respect player agency? |
| 4 | Does it respect Trust? |
| 5 | Does it preserve identity? |
| 6 | Does it avoid manipulation? |
| 7 | Does it fit existing architecture? |

If **any** answer is **NO**, the feature is rejected.

Additional freeze-specific gates still apply (e.g. F2.16 Premium poison tests · F2.19 human-before-AI · F2.26 commerce bans · F2.27 privacy bans).

This framework is necessary.

It is not always sufficient — prior constitutions remain binding.

---

# 6. Architecture Governance

Future architecture must remain **modular**.

| Law |
|-----|
| No feature may become mandatory for using GMRLOG’s cultural core |
| Optional layers remain optional |
| Core identity remains stable |
| IA tab roots remain frozen unless F2.1 is explicitly amended |
| Guests / extensions / commerce never become foundations (F2.21 · F2.28 · F2.26) |

Modularity protects Digital Home from hostage features.

---

# 7. Cross-Sprint Conflict Resolution

If two future features — or two documents — conflict:

**Priority order:**

| Priority | Authority |
|----------|-----------|
| 1 | North Star |
| 2 | Master Product & Design Direction |
| 3 | Product Constitution (**this document · F2.29**) |
| 4 | Earlier constitutional sprint |
| 5 | Later sprint |

Later documents never silently overwrite earlier constitutions.

Amendments must be **explicit**, dated, and LOCK-aware — never drift by implication.

F2.16 Premium ethics and F2.17 Trust remain especially hard gates when money or power is involved.

---

# 8. Design Consistency

Every future experience should immediately feel like GMRLOG.

| Prefer | Over |
|--------|------|
| Consistency | Novelty for its own sake |
| Recognition | Trends |
| Story Ember discipline | Generic AI aesthetics |
| F1 signatures & composition | Parallel visual systems |

Compose existing components and freezes.

Do not invent a second design language.

---

# 9. Product Review Philosophy

Every major proposal should pass four reviews:

| Review | Asks |
|--------|------|
| **Product Review** | Digital Home · pillars · architecture fit |
| **Trust Review** | Safety · fairness · transparency · appeals kinship (F2.17 · F2.27) |
| **Identity Review** | Player authorship · reputation integrity · no metric captivity (F2.5 · F2.13) |
| **Culture Review** | Gaming culture centrality · anti-clone · recognizability |

If **any** review fails, the proposal returns for redesign.

Reviews are constitutional — not theatrical.

---

# 10. Innovation Framework

Innovation is encouraged.

Imitation is not.

| May | Must never |
|-----|------------|
| Borrow ideas / behaviors | Borrow identities / UI systems of other platforms |
| Invent new expressions under constitution | Become “Steam+Discord+Reddit” by collage |
| Pursue recognizability | Pursue familiarity as strategy |

The goal is to become **recognizable**, not familiar.

---

# 11. Deprecation Philosophy

Removing features should be **extremely rare**.

| When removal happens | Goal |
|----------------------|------|
| Clarity increases | Product becomes clearer — not merely smaller |
| Continuity preserved | Historical / legacy meaning kept when possible (F2.14) |
| Agency respected | No dark removal of player memory or control |

Deprecation is stewardship.

Not churn theater.

---

# 12. Future Expansion Rules

Future modules may introduce:

| Allowed expansion kinds |
|-------------------------|
| New content types |
| New communities |
| New integrations |
| New AI capabilities |
| New creator tools |
| New organization types |

They may **never** violate existing constitutional principles.

Expansion strengthens the ecosystem.

It never rewrites it.

F3+ may specify experiences.

It may not repeal F2 laws.
