# 1. Mission

Events exist to **celebrate gaming culture**.

Not to manufacture engagement.

---

# 2. Core Philosophy

Gaming already has meaningful moments.

GMRLOG should **recognize them** — not invent artificial ones.

| Recognize | Invent (forbidden spirit) |
|-----------|---------------------------|
| Real launches, anniversaries, culture festivals | Fake FOMO seasons for retention |
| Community-led celebrations | Checklist theater |
| Creator/editorial specials tied to games | Platform-first “event grind” |

**Gaming remains the protagonist.**

---

# 3. Event Types

Architecture categories only:

| Type |
|------|
| Game Launches |
| Major DLC Releases |
| Anniversaries |
| Community Festivals |
| Seasonal Events |
| Charity Events |
| Developer AMAs |
| Community Challenges |
| Global Gaming Events |
| Creator Events |
| Editorial Specials |
| Future Live Events |

No type permanently dominates Discover or Home.

---

# 4. Seasonal Philosophy

Seasons reflect **gaming** — not the platform.

| Never | Instead (directional) |
|-------|------------------------|
| Battle Pass Seasons | Summer Gaming |
| XP Seasons | Halloween Horror Month |
| Ranked Seasons | RPG Week · Indie Festival |
| | Retro Month · Winter Backlog Season |

Kinship with Profile **Seasons** memory (F2.5.1) — taste chapters, not battle-pass chapters.

# 6. Discover Integration

Events appear **naturally** inside Discover (F2.10).

**Never dominate.**

Discover answers:

> “What interesting gaming moment is happening?”

Taste-first · explainable when recommended · Seasonal Picks / Editorial / Events surfaces reserved.

---

# 7. Home Integration

Events appear **only when meaningful** (F2.3 · F2.7).

| Allowed sparse forms | Forbidden |
|----------------------|-----------|
| Silent banner | Replacing Home heartbeat |
| Editorial section | Event takeover feed |
| Featured Community | Infinite event cards |
| Featured Collection | |

Home remains “what is happening in gaming culture now” — events are guests, not hosts.

# 10. Legacy Integration

Events become **chapters** inside the player’s history (F2.14 Legacy · Journey Timeline).

Not temporary checklists. Not grind tracks that expire into nothingness of meaning.

---

# 11. Notifications

| Relevant |
|----------|
| Personally relevant |
| Community relevant |
| Game relevant |

Never:

> “Come back now!”

Future Events category reserved. Calm · digest-capable · no FOMO countdown manipulation.

```
Events

```

# 15. Anti-Gamification

**Explicitly forbid:**

| Forbidden |
|-----------|
| Event XP |
| Event Battle Pass |
| Event Currency |
| Daily Event Quests |
| Login Rewards |
| FOMO Countdown Manipulation |
| Artificial Scarcity |

Events **celebrate**. Never manipulate.

Align F2.13 · F2.14 anti-gamification.

# 18. Audit Checklist

- [ ] Events celebrate gaming culture — not manufactured engagement  
- [ ] Recognize real moments — do not invent artificial retention seasons  
- [ ] No battle passes · seasonal XP · event currencies  
- [ ] No daily event quests · login rewards · FOMO countdown manipulation · artificial scarcity  
- [ ] Seasonal philosophy reflects gaming — not platform grind  
- [ ] Discover integration natural — never dominates  
- [ ] Home integration sparse — never replaces heartbeat  
- [ ] Game integration secondary to game identity  
- [ ] Profile remembers participation as memories  
- [ ] Legacy continuity — chapters, not disposable checklists  
- [ ] Notifications calm · personally/community/game relevant only  
- [ ] Creator integration amplifies — creators do not own events  
- [ ] Community integration culture-first  
- [ ] Relationship Graph maintained  
- [ ] Future conferences/showcases/awards reserved  
- [ ] Compatible with F2.1–F2.14  
- [ ] No new bottom tab · compose existing surfaces  
- [ ] No UI · backend · algorithms · monetization · implementation · F2.15.1  
- [ ] MVP event scope declared (§19) — one Event destination · Discover hub entry · sparse Home presence

# 19. MVP Final Integration Amendment — Events MVP

**Amendment:** MVP Final Integration Amendment (July 2026). Events are **MVP scope**, not Version 2. §1–§18 philosophy (celebration over manufactured engagement, anti-gamification) is unchanged.

## 19.1 MVP event families

Events are one **Shared Destination** with variants — not multiple products. **Events belong to Discover** (hub entry under Discover; detail remains Shared).

Supported event types:

| Family | Anchor |
|--------|--------|
| Game | §3 · §8 |
| Community | §3 · §5 · §13 |
| Tournament | §3 · F2.11 esports culture |
| Seasonal | §3 · §4 |

## 19.2 Product relationships in MVP

| Relationship | Rule |
|--------------|------|
| Discover | **Owner of event discovery** — Events Hub entry (§6); never dominating the hub |
| Home | May display event activity sparsely (§7) — events remain guests, never hosts |
| Game | Exposes relevant event signals without becoming an event page (§8) |
| Community | Community events are presented in the community's context (§5 · §13) |
| Profile · Legacy | Participation becomes memory and chapter (§9 · §10) |
| Notifications | Calm, relevance-bound only (§11) |

## 19.3 MVP laws

| Law |
|-----|
| Events belong to Discover — hub entry under Discover, detail as Shared Destination; no new tab (F2.1) |
| Participation is deliberate and reversible where the event allows |
| Time information may be presented; countdown coercion, artificial scarcity and FOMO pressure remain forbidden (§15) |
| No event currencies · no passes · no XP · no login rewards (§15) |
| Tournaments recognize competitive culture — they do not introduce ranking economies or prize commerce (Version 2) |

## 19.4 Still not MVP

| Deferred |
|----------|
| Live event streaming · conferences · showcases · awards infrastructure (§16) |
| Paid or Premium-gated event access (F2.16 · F2.26) |
| Creator-monetized events (F2.12) |

## 19.5 Architecture references

| Reference | Contains |
|-----------|----------|
| F5.1 §17.8 · §34 | Event as Shared Destination · Events Hub under Discover |
| F5.2 §6.4 | Event activity in Home taxonomy |
| F5.3 | Events Hub · Event Detail screens |
| F5.4 §38.1.2 | Event card behavior · anti-urgency law |
