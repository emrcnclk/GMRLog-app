# 1. Mission

Define the immutable UX philosophy of GMRLOG.

F2 answered:

> “What should GMRLOG be?”

F3.1 answers:

> “How should GMRLOG feel?”

This document defines **interaction philosophy only**.

Not implementation.

Not UI.

Not components.

Not colors.

Not backend.

Not frontend.

---

# 2. UX Philosophy

GMRLOG should feel like:

> **a calm premium gaming home**

| Never feel like |
|-----------------|
| A social media app |
| A dashboard |
| A productivity tool |
| A content factory |

Players should always feel:

| Feeling |
|---------|
| Comfortable |
| Focused |
| In control |
| Never rushed |

Align Digital Home (F2.5.1) · calm agency (F2.20) · Trust before engagement (F2.17 · F2.22).

The interface should feel:

| Quality |
|---------|
| Calm |
| Confident |
| Predictable |
| Consistent |
| Human |

Every screen should answer:

> “What do I want to do?”

before asking:

> “What should I click?”

---

# 3. Interaction Principles

## Prefer

| Prefer |
|--------|
| Less clicks |
| Less clutter |
| Less interruptions |
| More context |
| More clarity |
| More ownership |

## Never design for

| Never |
|-------|
| Engagement loops |
| Addiction |
| Confusion |
| Surprise mechanics |
| Dark patterns |

## Interaction values

| Value | Meaning |
|-------|---------|
| Clarity | Intent is legible before chrome |
| Confidence | Actions feel safe to take |
| Continuity | Same patterns mean the same thing |
| Respect | No coercion · no FOMO theater (F2.9 · F2.23) |
| Agency | Refuse, undo, leave — always available where constitution requires (F2.20) |

Human agency always wins (F2.19 kinship when suggestions appear).

---

# 4. Navigation Philosophy

Navigation must always feel:

| Quality |
|---------|
| Obvious |
| Stable |
| Predictable |

## Laws

| Law |
|-----|
| No hidden primary actions |
| No mystery navigation |
| No gesture-only critical actions |
| Tab roots remain F2.1: Home · Discover · Library · Notifications · Profile |
| Composer remains FAB + contextual — not a sixth tab |
| Deep links resolve to clear places — not ambiguous stacks |

IA freeze (F2.1) is UX law here.

Navigation explains the house.

It does not invent a new house.

---

# 5. Cognitive Load Philosophy

Every screen should have **one primary purpose**.

Secondary actions should never compete with the main action.

| Reduce | Avoid |
|--------|-------|
| Parallel competing CTAs | Information overload |
| Nested decisions on first paint | Urgency-first UX (F2.18) |
| Surprise state changes | Flashing / demanding interfaces |

The platform should feel calm — not demanding (F2.18 Cognitive Accessibility kinship).

One job per section remains Master / prior design law — F3.1 makes it interaction law.

---

# 6. Interaction Density

Density serves comprehension.

Never spectacle.

| Sparse where | Dense only when |
|--------------|-----------------|
| Recommendations (F2.3 · F2.19) | Archive browsing needs structure (F2.6) |
| Home magazine rhythm | Player explicitly seeks tools |
| First viewport of branded moments | Reading long-form needs comfortable measure — not cram |

Less interruption beats more opportunity.

Optional layers stay optional (F2.29 Architecture Governance).

---

# 7. Reading Experience

Reading is **first-class** (F2.12 · F2.18).

| Surfaces |
|----------|
| Reviews |
| Guides |
| Articles |
| Collections |

must feel effortless.

| Always | Never |
|--------|-------|
| Prioritize comprehension | Sacrifice readability for density |
| Comfortable pacing | Engagement chrome over prose |
| Spoiler respect in interaction | Surprise spoilers as “engagement” |

Long-form remains first-class culture — not a secondary mode.

---

# 8. Gaming-first Feel

The product should feel like:

> **Steam meets Letterboxd** *(behaviors & emotional references only — never UI copies)*

| Not |
|-----|
| TikTok |
| Instagram |
| LinkedIn |

Gaming culture is the common ground (F2.8).

Taste, journey, library, and game graph lead interaction — not clout performance.

Relationship-first Game Experience (F2.4) and identity-first Profile (F2.5) remain the feel of “home,” not “feed casino.”

---

# 9. Consistency Rules

| Rule |
|------|
| Same action · same pattern · same expectation |
| Recognition over novelty (F2.29 · Master) |
| Compose F1 signatures — do not invent parallel interaction dialects |
| Contextual controls mirror Settings truth (F2.20) |
| Suggestions remain explainable and dismissible when present (F2.19) |

Consistency is comfort.

Inconsistency is cognitive tax.

---

# 10. Emotional Design

The product should make users feel:

| Desired |
|---------|
| Comfortable |
| Welcome |
| Recognized |
| Safe |
| Curious |

| Never |
|-------|
| Anxious |
| Judged by metrics (F2.23) |
| Hunted by invites (F2.25) |
| Defending themselves from the platform (F2.17 emotional goal) |

Emotional pacing is slow enough to think.

Fast enough to feel alive — never frantic.

---

# 11. Micro Friction

Micro friction is intentional resistance that **protects**.

| Good friction | Bad friction |
|---------------|--------------|
| Confirm destructive actions | Guilt before leaving |
| Spoiler gates | Fake scarcity |
| Clear consent before expanding data/AI scope (F2.27 · F2.19) | Re-enabling refused suggestions |
| Pause before irreversible identity damage | Endless mandatory tutorials |

Friction for care.

Never friction for retention.

---

# 12. Trust Through UX

Trust is felt in interaction — not only in policy (F2.17 · F2.27).

| UX builds trust when |
|----------------------|
| Outcomes match labels |
| Explanations appear without mystery |
| Mistakes are recoverable |
| Privacy controls are findable |
| Commercial / AI / imported signals are honest when shown (F2.26 · F2.21 · F2.19) |

No dark patterns.

No manipulative defaults.

No “recommended because we said so” as interaction voice (F2.20).

---

# 13. Error Philosophy

Errors should **educate**.

Never blame users.

Always explain:

| Always |
|--------|
| What happened |
| Why |
| How to recover |

| Never |
|-------|
| Shame |
| Dead ends without exit |
| Error as engagement bait |
| Silent failure that looks like success |

Errors protect Digital Home continuity.

They do not punish curiosity.

---

# 14. Learning Curve

GMRLOG should be learnable without becoming a tutorial product.

| Prefer | Avoid |
|--------|-------|
| Progressive disclosure | Forced onboarding gauntlets |
| Identity discovery over feature tour (F2.2.1) | Feature dump on first session |
| Browse-first where allowed | Hostage walls for culture reading |
| Stable patterns that teach by repetition | Constantly reinvented gestures |

Mastery grows with use.

It is not a grind.
