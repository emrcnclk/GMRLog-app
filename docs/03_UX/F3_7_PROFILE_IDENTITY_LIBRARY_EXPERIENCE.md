# 1. Mission

Define how a player experiences their **Digital Home**.

The profile is home.

Not a résumé.

The library is memory.

Not inventory.

Align North Star: lifelong gaming identity felt as place — not as performance dashboard.

---

# 2. Digital Home Philosophy

Digital Home (F2.5.1) is the emotional center of identity UX.

| Always | Never |
|--------|-------|
| Belonging · continuity · authorship | Optimization anxiety |
| Calm premium gaming home (F3.1) | Social-status hierarchy |
| Player as protagonist | Profile as product |
| Memory before metrics | Metric-first layouts |

Visitors see identity.

Owners experience home.

Same structure (F2.5 hierarchy) — different emotional contract.

---

# 3. Profile Experience

Profile tab is the identity anchor (F3.2 · F2.1).

| Self-view should feel | Visitor-view should feel |
|-----------------------|--------------------------|
| Return to my rooms | Meeting someone’s gaming self |
| Tools available without cluttering first meaning | Story first · actions secondary |
| Settings reachable as control panel | No owner chrome |

| Profile experience may | Must never |
|------------------------|------------|
| Surface Identity · Journey · Creator vertical · entry to Library mirrors | Open as a settings dump |
| Keep Gamer Identity Header as orientation (F1) | Lead with vanity score walls |
| Allow Messages / Premium / hubs as children | Promote those to rival homes |

No comparison-first experience on arrival.

---

# 4. Identity Presentation

Identity presentation follows F2.5.1: story · DNA · Known For · shelf — not badge walls.

| Present | Never present as primary |
|---------|--------------------------|
| How they play · what they’re known for (qualitative) | XP · karma · leaderboard energy (F2.13) |
| Taste language | Completion percentage as worth |
| Authored highlights | Imported sync noise as self (F2.21) |

## Known For

Known For is recognition — not a scoreboard.

Presentation stays calm · sparse · explainable in spirit of Trust (F2.17).

No social-status hierarchy chrome.

## Gamer Identity

Gamer Identity is lived language.

Not a résumé header optimized for strangers.

---

# 5. Library Experience

Library is the **personal archive** (F2.6) — memory, not launcher.

| Library should feel | Must never feel |
|---------------------|-----------------|
| Continuity of owned meaning | Storefront inventory |
| Continue Playing as living relationship | Guilt backlog siren |
| Wishlist as aspiration | Checkout coercion |
| Backlog as intentional | Shame for unfinished |

| Surface | Experience law |
|---------|----------------|
| Continue Playing | Warm return — not streak pressure |
| Backlog | Player-paced — no completion guilt |
| Wishlist | Desire without purchase identity |
| Hidden Archive | Sealed room — never surprise exposure |
| Activity / history | Memory trail — not grind log |

Library search/filter obey F3.6 · stay archive-scoped when appropriate (F2.6 / F2.10 split).

---

# 6. Collection Experience

Collections express **personality**.

Not optimization.

| Collections may | Must never |
|-----------------|------------|
| Curate taste · stories · shelves | Become ranking weapons |
| Grow with ownership pride | Demand completionism |
| Appear on Identity Shelf when player chooses | Force public performance of every shelf |

Collection growth is authorship.

Not a productivity metric.

Empty collection states inspire without guilt (F3.6).

---

# 7. Journey & Legacy

Journey reflects **life**.

Not progress pressure (F2.4 · F2.14).

Legacy preserves **memories**.

Not achievements alone.

| Journey / timeline should | Must never |
|---------------------------|------------|
| Narrate continuity · seasons · On This Day kinship | Gamify into battle-pass chapters |
| Honor emotional moments already logged | Invent milestones for retention |
| Feel readable (F3.1 · F3.3) | Metric strip as the story |

Activity history and timeline philosophy: calm chronology · player-owned meaning · no FOMO “catch up” theater (F2.9).

---

# 8. Personal Organization

Organization supports ownership of Digital Home (F2.20 · F2.16 tools).

| Organization may | Must never |
|------------------|------------|
| Shelves · order · folders as calm tools | Create two cultures of belonging |
| Premium deepen tools — not identity caste | Sell reputation via organization chrome |
| Progressive disclosure for advanced tools (F3.3) | Hide privacy / Hidden Archive controls |

Personal organization is housekeeping of home.

Not lifestyle optimization content.

---

# 9. Editing Philosophy

Editing supports **ownership**.

Never perfectionism.

| Editing should | Must never |
|----------------|------------|
| Make identity/library revisable | Trap in mandatory completeness |
| Feel safe to try · easy to reverse | Punish imperfect profiles |
| Keep draft dignity for creator vertical (F2.12) | Turn edit into public performance rehearsal |
| Validate kindly (F3.6) | Shame “incomplete gamer” |

Profile editing experience: owner tools secondary to living home on first paint — available without anxiety.

---

# 10. Public vs Private Experience

Private vs public is agency (F2.17 · F2.20 · F2.27).

| Law |
|-----|
| Defaults calm · openness intentional |
| Self-view sees owner controls · private shelves · Hidden Archive |
| Visitor-view never leaks private rooms |
| No public-pressure architecture that withholds belonging until performative openness |
| Privacy not Premium (F2.16) |

Visitors see the identity the owner chose to share.

Owners never feel the house was redesigned for an audience first.

---

# 11. Accessibility Relationship

Digital Home must remain a home for every body (F2.18 · F3.1–F3.6).

| Implication |
|-------------|
| Identity and archive navigable without gesture-only critical paths |
| Reading of journey / collections first-class |
| Hierarchy: identity before tools (F3.3) |
| Empty/loading/error states non-guilt · recoverable |
| Reduce Motion preserves orientation in Profile/Library transitions (F3.5) |

---

# 12. Consistency Rules

| Rule |
|------|
| Profile always means Digital Home — not a shifting résumé mode |
| Library always means archive — not launcher |
| Self vs visitor chrome differs · structure does not betray F2.5 |
| Known For / Journey / Collections share calm grammar |
| Continue Playing · Wishlist · Hidden Archive keep distinct emotional jobs |
| Creator vertical grows on Profile — never steals the home metaphor (F2.12) |
| Settings remains control panel via Profile — not the living room |

---

# 13. Anti-Manipulation

Explicit bans:

| Ban |
|-----|
| Metric-first layouts |
| Vanity pressure |
| Comparison-first experience |
| Profile optimization anxiety |
| Completion guilt |
| Public-pressure architecture |
| Social-status hierarchy |
| Streak / grind presentation of journey |
| Empty-state shame for thin libraries |
| Forced showcase of private shelves |
| Sold “profile boost” aesthetics as reputation (F2.16 · F2.26) |
| Leaderboard energy on Identity |

If a Profile/Library pattern’s best argument is “it increases sharing,” it is illegitimate unless it also strengthens home without pressure.

---

# 14. Future Ready

Reserve architecture only:

| Capability |
|------------|
| Richer Digital Home personalization under F2.20 / F2.16 ethics |
| Yearbook / biography presentation kinship (F2.14 · F2.23) |
| Deeper collection organization tools |
| Clearer imported-vs-authored labeling in Library (F2.21) |
| Visitor highlight modes that never override owner privacy |

No UI · no implementation.

---

# 15. Emotional Goal

Identity & Library should feel like:

> “This feels like my gaming home.”

Never:

> “I feel like I’m managing a profile.”

Never:

> “I feel judged by my library.”

# 17. MVP Final Integration Amendment — Communities · Achievements · Connected Accounts · Library Import

**Amendment:** MVP Final Integration Amendment (July 2026). §1–§16 experience philosophy is unchanged. This section extends Digital Home UX guidance for MVP surfaces.

## 17.1 Communities (shared gaming spaces)

Communities should feel like **shared gaming spaces** — rooms of belonging around games, not obligation engines.

| Surface | Experience rule |
|---------|-----------------|
| Members | Calm, community-driven people presence — never follower vanity (§10) |
| Feed | Calm, community-driven culture stream — games over egos |
| Activity | Calm, community-driven record of what happened — never an engagement scoreboard |

| Law |
|-----|
| Shared gaming space first — never Discord-surrogate chat pressure |
| Never create FOMO pressure |
| Never create obligation loops (join · post · return · or lose belonging) |
| Leaving is quiet and unpunished |
| Membership size and activity volume are never status pressure |

## 17.2 GMRLOG achievements

| Rule |
|------|
| Achievements read as autobiography — “this is what I have lived” — not as a scoreboard (§4) |
| Progress is honest and pressure-free: no completion guilt, no “almost there” nudging (§13) |
| Unearned achievements are context, never accusation |
| The player controls what visitors see (§10) |
| Achievements sit alongside Journey and Legacy as memory, never above them (§7) |

## 17.3 Connected accounts

| Rule |
|------|
| Connecting feels like convenience, never like proving identity (§2) |
| Zero connections is a complete Digital Home — no incomplete-profile framing |
| Disconnecting is calm, honest about consequences and never punished (§9 agency) |
| External accounts never become status decoration on identity |

## 17.4 Library import (Steam)

| Rule |
|------|
| Import feels like help with chores, not like the platform authoring the archive (§5) |
| Imported games are candidates for meaning; the player's logging remains the story (§5 · §8) |
| Ownership is not achievement: owning many games is never presented as identity (§13) |
| Hidden Archive and privacy feelings stay intact for imported entries (§10) |
| Import never triggers completion guilt about the backlog (§13) |
