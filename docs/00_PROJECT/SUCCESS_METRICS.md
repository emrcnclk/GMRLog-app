# Success Metrics

## Purpose

This document defines how success is measured across every stage of GMRLOG's lifecycle.

The objective is to ensure every product, design, engineering, and business decision can be evaluated using measurable outcomes rather than subjective opinions.

Every feature introduced into the platform must improve at least one of the metrics defined in this document.

---

# Product Success Philosophy

Success is not measured by downloads.

Success is not measured by registered users.

Success is measured by habit formation.

A successful GMRLOG user naturally opens the application whenever they:

* Start a new game.
* Finish a game.
* Unlock an achievement.
* Discover a recommendation.
* Want to discuss gaming.
* Want to check what friends are playing.
* Want to publish a review.
* Want to organize their collection.

The platform should become part of the player's gaming routine.

---

# North Star Metric

## Monthly Active Logged Players (MALP)

Definition:

The number of unique users who have performed at least one meaningful gaming action within the last 30 days.

Meaningful actions include:

* Logging a game
* Publishing a review
* Starting a play session
* Completing a game
* Creating a tier list
* Commenting
* Posting
* Messaging
* Updating a collection
* Following a developer

Simple application opens do not count.

# Quarterly Product Review

Every quarter the leadership team must evaluate:

What increased engagement?

What reduced engagement?

What features are ignored?

What communities are growing?

What genres are trending?

Which recommendations perform best?

Which onboarding steps create drop-off?

Which countries show strongest growth?

The roadmap must evolve based on measurable evidence rather than assumptions.
